# PRD: Shapes Kinetic Corner Grab

**Status:** Actioned and verified on 2026-07-13.

**Review record:** Senior PRD review approved after the physics-specialist review; final implementation review approved after production mouse, touch, collision, cadence, lifecycle, reduced-motion, configuration, and visual verification.

## Introduction/Overview

Upgrade the Home Shapes simulation so a visitor can press any visible dot, including a corner dot, and use that exact material point as a hard pivot beneath their mouse, pen, or finger. While the pointer remains pressed, the shape must rotate around the grabbed point under gravity, pointer movement, and collisions. On release, the body must retain the linear and angular momentum generated by the manipulation instead of discarding most of it.

The current Shapes runtime already stores a local grab point, pins it to the pointer, derives body velocity, and supports collision impulses. However, its pointer torque is ad hoc, the held body is removed from rotational collision response, input velocity uses only the latest event, and normal release reduces translation to `42%` and rotation to `25%`. This feature replaces that energy-suppressing path with a deterministic point-constraint interaction while preserving the existing dot-cluster shapes, gravity, wall behavior, palette, responsive density, and Canvas 2D runtime.

Confirmed product decisions:

- The grabbed point is perfectly pinned to the pointer with no visible lag.
- Normal release preserves filtered linear and angular momentum, subject to safety caps.
- Collisions can rotate the held shape around the grabbed point.
- Reduced-motion users keep the interaction with lower throw/spin limits and faster settling.
- Expert tuning controls are saved through the canonical authored design configuration.
- The exact pointer anchor takes precedence over full wall containment when the pointer requests a geometrically impossible edge pose; wall contacts must still rotate the body toward the least-penetrating feasible pose.

## Goals

- Keep the exact grabbed dot beneath the active pointer throughout a drag, including during gravity and collisions.
- Make off-centre manipulation visibly create rotation and transferable kinetic motion.
- Preserve stable linear and angular momentum after a normal release.
- Allow held shapes to collide with and transfer energy to the other compound shapes without detaching from the pointer.
- Produce equivalent mouse and touch behavior across desktop and mobile input paths.
- Keep the physics loop bounded, allocation-conscious, and stable at supported frame rates.
- Make all new tuning values complete across live apply, canonical save, reload, flattening, and preview.
- Add repeatable browser evidence proving the interaction rather than relying on subjective manual observation alone.

## User Stories

### US-001: Grab an exact point on a shape

**Description:** As a visitor, I want the dot I press to remain exactly beneath my pointer so the shape feels physically attached to my hand.

**Acceptance Criteria:**

- [x] Pressing any visible dot in a settled Shapes body starts a single active grab for that body and pointer ID.
- [x] The local material point selected on pointer-down remains the constraint anchor until release or cancellation.
- [x] During pointer movement inside the canvas, the world-space anchor stays within `1.5` CSS pixels, converted once to `1.5 × DPR` backing-store pixels, of the pointer target after each completed physics frame.
- [x] Starting a grab does not snap the shape's angle or move the selected point away from the initial press position.
- [x] When an edge pose makes exact pinning and complete wall containment mutually impossible, the anchor remains exact and wall contacts rotate the body toward the least-penetrating pose without introducing unbounded energy.
- [x] A press in empty space continues to use the existing sweep interaction rather than creating a grab.
- [x] Only the primary pointer and primary mouse button can start a grab.
- [x] `npm run check:site` passes.
- [x] Verify in browser using dev-browser skill.

### US-002: Rotate a held shape through physical manipulation

**Description:** As a visitor, I want an off-centre grab to rotate under gravity and my movement so I can swing or spin the shape around my finger.

**Acceptance Criteria:**

- [x] Holding a corner or other off-centre dot leaves rotation as an active degree of freedom around the pinned point.
- [x] Gravity generates torque around an off-centre held point.
- [x] Pointer motion contributes bounded angular momentum through `deltaOmegaPointer = mass × cross(rotatedGrabOffset, deltaAnchorVelocity) / pivotInertia`; it does not use the current arbitrary velocity-as-torque calculation.
- [x] A deterministic `180–260` CSS-pixel curved or lateral gesture from an off-centre grab changes absolute angular velocity by at least `0.35 rad/s` before release.
- [x] In the deterministic audit fixture, the same gesture at the selected corner produces at least `1.5×` the absolute angular-velocity change of a grab within `0.2 × body.radius` of the centre.
- [x] Angular response is timestep-aware and does not depend on a fixed number of rendered frames.
- [x] The new constraint, pointer-sampling, and audit-diagnostic paths add no arrays or short-lived objects inside per-substep or per-contact loops; pre-existing allocations remain out of scope unless profiling shows they prevent the performance gate.

### US-003: Preserve throw and spin momentum on release

**Description:** As a visitor, I want the shape to continue moving after I let go so my gesture has a convincing physical result.

- [x] A release after a fast gesture retains non-zero velocity and angular velocity when the corresponding pre-release values exceed fixed internal thresholds of `30 CSS px/s` and `0.08 rad/s`.
- [x] One stationary render frame immediately before release does not erase an otherwise valid recent throw.
- [x] Linear and angular release speeds are clamped to authored safety limits.
- [x] Pointer cancellation does not use the throw estimator; it retains only a finite, safety-capped constrained state and leaves the body valid.
- [x] Post-release bodies continue through existing gravity, damping, wall contacts, and body collisions.

## Functional Requirements

- FR-1: Pointer-down on a visible Shapes dot must store the exact local-space material point beneath the pointer as the active constraint anchor.
- FR-2: While the pointer target remains inside the canvas, the active constraint must keep that material point within `1.5` CSS pixels, converted to `1.5 × DPR` backing-store pixels, after every completed physics frame.
- FR-3: The constraint must preserve rotation as the held body's free degree of freedom rather than locking its angle.
- FR-4: Gravity, pointer motion, body collisions, and wall contacts must be able to change angular velocity around an off-centre anchor.
- FR-5: Pointer-driven angular response must use `deltaOmegaPointer = mass × cross(r, deltaAnchorVelocity) / Ipivot`, where `r` is the rotated centre-to-anchor vector and `Ipivot = Icenter + mass × |r|²`; the existing arbitrary `cross(grabPoint, pointerVelocity) × mass × 0.09 × dt` path must be removed.
- FR-6: The exact hard pin must use a reduced-coordinate held-body model with one free degree of freedom: `center = anchor - r`, `vCenter = vAnchor - omega × r`, `vContact = vAnchor + omega × (contact - anchor)`, and `Ipivot = Icenter + mass × |r|²`.
- FR-7: The runtime must keep a fixed-size, bounded history of recent pointer samples containing canvas position and monotonic time.
- FR-8: Normal release must retain filtered linear and angular momentum using configurable gains defaulting to `1.0`.
- FR-9: Cancellation must not inject new release momentum.
- FR-10: Linear velocity must remain capped by `shapesMaxSpeed`; angular velocity must remain capped by the new authored maximum angular speed.
- FR-11: Reduced motion must retain direct manipulation while scaling release limits and increasing post-release settling.
- FR-12: The held body must remain collision-active. Its contact inverse mass along normal `n` must be `cross(contact - anchor, n)² / Ipivot`, and a contact impulse `J` must change held rotation by `deltaOmega = cross(contact - anchor, J) / Ipivot`. The pin reaction absorbs forbidden translation.
- FR-13: Empty-space sweep behavior and its existing controls must remain unchanged.
- FR-14: The interaction must support primary mouse, pen, and touch pointer paths and must reject unrelated pointer IDs during an active grab.
- FR-15: All active-grab exit paths must leave `state.drag === null` and every Shapes body with `isDragged === false`.
- FR-16: The physics implementation must remain bounded to the five compound bodies and one active point constraint, with no new dependency or engine replacement.
- FR-17: New configurable values must support live apply, canonical save, reload, flattening, and production preview parity.
- FR-18: Automated browser verification must fail on excessive anchor error, missing release momentum, missing angular response, stale drag state, non-finite body state, or speed-cap violations.
- FR-19: Shapes must run bounded local physics substeps at a target step no larger than `1/120s`, using `ceil(frameDt / targetStep)` with a maximum of four substeps. This relies on the shared custom-step invariant that frame delta is capped at `0.033s`.
- FR-20: For each held-body local substep, the solver must interpolate the anchor target, derive bounded anchor-velocity change, apply pointer and gravity torque with pivot inertia, apply per-second held damping, integrate angle, reconstruct centre position/velocity from the exact anchor, solve contacts through pivot-space impulse and bounded angular penetration correction, then reconstruct the exact centre/contact state once more.
- FR-21: Exact anchoring takes precedence over complete wall containment only when the pointer requests an infeasible edge pose; the runtime must still minimize wall penetration through angular contact response.
- FR-22: Held penetration correction must use bounded angular projection proportional to `cross(contact - anchor, normal) / (cross² + softness)` and must not be added to angular velocity.

## Non-Goals

- No change to the number, geometry, dot construction, palette, ordering, or drop sequence of the five Shapes bodies.
- No visual helper lines, pivot markers, handles, rings, trails, or new pointer artwork.
- No multi-touch or simultaneous multi-body grabbing.
- No two-finger rotation, pinch scaling, resizing, tearing, bending, or soft-body deformation.
- No replacement of the Canvas 2D runtime or introduction of a third-party physics engine.
- No change to empty-space sweep behavior beyond preserving compatibility with the new grab state.
- No redesign of wall geometry, frame geometry, shell colours, title depth, Button Bar, or route behavior.
- No new sound or haptic effect unless separately requested.
- No commit, push, or deployment as part of this implementation unless explicitly requested.

## Design Considerations

- The interaction should read as grabbing a physical dot that belongs to a rigid compound object, not dragging a flat layer.
- The anchor is invisible. The existing dot geometry and material motion must communicate the constraint without helper graphics.
- Perfect pinning applies to position, not orientation: the shape must remain free to swing and spin around the held point.
- A normal release should feel energetic but controllable. Safety caps prevent touch noise or a single delayed frame from launching a body at an unreasonable speed.
- Grabbing near the centre should feel stable; grabbing a corner should create the strongest leverage and most obvious rotation.
- Existing cursor forms, canvas sizing, responsive density, light/dark palette behavior, and reduced-motion accessibility must remain intact.

## Technical Considerations

- Primary implementation surface: `react-app/app/src/legacy/modules/modes/shapes.js`.
- Shared pointer lifecycle changes, if required, belong in `react-app/app/src/legacy/modules/input/pointer.js` and must not regress other modes.
- State defaults and clamps belong in `react-app/app/src/legacy/modules/core/state.js`.
- Expert controls belong in `react-app/app/src/legacy/modules/ui/control-registry.js`.
- Authored defaults belong in `react-app/app/public/config/design-system.json`; `default-config.json` is generated through `npm run flatten:design-config`.
- Configuration documentation belongs in `docs/reference/CONFIGURATION.md`; the runnable behavior snapshot belongs in `docs/reference/MODES.md` if its interaction description changes materially.
- Use a reduced-coordinate hard pivot. While held, translation is prescribed by `center = anchor - rotate(grabLocal, angle)` and rotation is the only independent body degree of freedom.
- Use `Ipivot = Icenter + mass × |grabOffset|²`, `vCenter = vAnchor - omega × rotatedGrabOffset`, and `vContact = vAnchor + omega × (contact - anchor)` throughout the held path.
- Transfer pointer acceleration into angular momentum with `deltaOmegaPointer = mass × cross(rotatedGrabOffset, deltaAnchorVelocity) / Ipivot`. Interpolate the pointer target across local substeps and bound noisy `deltaAnchorVelocity` before applying it.
- The existing gravity torque sign is retained: `torqueGravity = -rotatedGrabOffset.x × mass × gravity`.
- For held contacts, use pivot-space effective inverse mass `cross(contact - anchor, normal)² / Ipivot`; apply contact torque as `deltaOmega = cross(contact - anchor, impulse) / Ipivot`. Do not mix centre-of-mass translation impulses into the held path.
- Correct held penetration by a bounded angular projection proportional to `penetration × cross(contact - anchor, normal) / (cross² + softness)`. Do not convert this positional correction into angular velocity. Near-zero leverage can leave residual penetration under the confirmed anchor-precedence rule.
- After pointer, gravity, damping, integration, and contacts, reconstruct the centre and contact velocities from the exact anchor so no contact correction can detach the selected material point.
- Reuse the Quote Puck's bounded five-sample, `120ms` release-estimation pattern conceptually, but keep Shapes sampling allocation-free with fixed scalar slots or a preallocated ring.
- Apply held damping as `omega *= exp(-shapesGrabAngularDampingPerSec × dt)` so results remain stable across different frame deltas.
- Run mandatory bounded mode-local substeps using `ceil(frameDt / (1/120))`, capped at four, rather than changing the shared engine cadence for every simulation.
- On normal release, estimate filtered anchor velocity from the fixed sample history, retain solved `omega`, compute `vCenter = vAnchor - omega × rotatedGrabOffset`, then apply configured gains and speed caps. Cancellation must not use this throw reconstruction.
- Use the existing audit-only `window.__ABS_HOME_AUDIT__.getGlobals()` exposure for deterministic fixture placement and `shapesState` inspection; do not add a new production diagnostic API unless the audit needs a smaller read-only snapshot.
- Add explicit window-blur and visibility-loss cancellation without coupling shared pointer code to Shapes state. If immediate mode cleanup needs a shared controller hook, keep it optional, generic, and limited to the previous mode runtime.
- Preserve unrelated worktree changes in shared configuration, state, controls, CSS, and documentation files.
- Before editing `state.js`, `control-registry.js`, `design-system.json`, or generated `default-config.json`, record their existing diff, patch only the Shapes blocks, run flattening once, and confirm the resulting diff preserves all unrelated authored and generated changes.

### Deterministic audit fixtures

- Use the square body at index `1`, set its angle, linear velocity, and angular velocity to `0`, place it at a safe canvas-centre fixture, and keep the other bodies pending or outside the fixture unless the collision case needs one.
- For pointer-spin and release tests, set Shapes gravity to `0`, disable unrelated body collisions, use a `220 CSS px` gesture over `240ms` with `12` evenly timed steps, and release while the pointer is still moving. Record the actual DPR and convert coordinates once.
- Test both a square corner anchor and the centre dot. The corner gesture must change absolute angular velocity by at least `0.35 rad/s` and by at least `0.25 rad/s` more than the centre gesture.
- Test gravity torque separately with a stationary off-centre anchor, authored gravity, and zero initial velocity; absolute angular velocity must change by at least `0.1 rad/s` within `250ms`.
- Measure release retention from the reconstructed release target immediately before pointer-up to the body state within `50ms` after pointer-up, with gravity and collisions disabled for this fixture.
- For held collision response, launch one isolated unheld body at `600 CSS px/s` into an off-centre contact on the held square. Held absolute angular velocity must change by at least `0.15 rad/s` within `300ms` while anchor error remains within tolerance.
- For cadence verification, the audit may use the existing exported `stopMainLoop()` plus direct browser imports of `stepShapes()` to drive identical fixtures with `1/60s` and `1/30s` frame deltas. Production behavior must not depend on the audit driver.
- Chromium desktop uses the real mouse path. Chromium mobile uses protocol touch input. WebKit uses the real mouse/pointer path. Save a compact JSON report and desktop/mobile before/after screenshots under `output/playwright/shapes-kinetic-grab/`.
