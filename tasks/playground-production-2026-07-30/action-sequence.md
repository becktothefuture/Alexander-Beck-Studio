# Playground Action Sequence

## Phase 0 — Preparation and mapping

1. Read project and skill authorities.
2. Record studio, Git, and process state.
3. Inspect the live reference with Playwright.
4. Run the four read-only mapping lanes.
5. Reconcile rendering model, shell ownership, configuration gaps, and verification surfaces.
6. Create this durable packet.

## Phase 1 — Isolated foundations

1. Build pure spatial math and tests.
2. Build the canonical content source, local placeholders, validation, and media helpers.
3. Build the route-local React view, semantic collection, lightbox, and CSS.
4. Add the route entry and serialized shared route registration.
5. Run route registry, content, layout, and lint checks.

## Phase 2 — Configuration and integration

1. Add normalized canonical `playground` defaults and bounds.
2. Add one panel schema, live apply, diagnostics, actions, and canonical save snapshot.
3. Prove save and reload preservation.
4. Prove flatten/build preservation.
5. Integrate shared palette, theme, sound, haptics, readiness, entrance, and teardown.

## Phase 3 — Tests and documentation

1. Add deterministic tests for modulo, coverage, placement, growth, validation, drag guard, URL selection, and config normalization.
2. Add `npm run audit:playground`.
3. Extend production route matrices and certification.
4. Update design, architecture, configuration, styleguide, component, content-authoring, and command references.

## Phase 4 — Review and proof

1. Run a separate read-only integrated reviewer.
2. Resolve all valid critical, high, and medium findings.
3. Run required source gates.
4. Run browser audits serially.
5. Capture and inspect the visual matrix.
6. Complete `final-verification-record.md` with exact evidence.

## Stop conditions

Stop only for an external blocker, permission boundary, or a product choice that materially changes the implementation. Do not start, stop, duplicate, publish, push, or deploy shared processes without explicit authorization.
