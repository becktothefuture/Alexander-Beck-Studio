# PRD 01: Route Model And Bottom Tabs

## 1. Overview

Introduce a persistent bottom route-tab model for Home, Contact, Portfolio, and About Me. Contact and About become real route surfaces. Portfolio remains gated, but the locked state lives on the Portfolio route rather than redirecting to a home modal.

## 2. Goals

- Add route-derived active state for all bottom tabs.
- Make Contact a route page.
- Make About a non-gated route page.
- Make Portfolio the only gated route.
- Add direct multi-entry support for Contact and About.
- Create the bottom tab skeleton and stable selectors used by later PRDs.

## 3. User Stories

### US-001: Persistent Route Tabs

As a visitor, I can always see the main route tabs at the bottom of the shell and understand which area is active.

Acceptance criteria:

- [ ] Home tab is icon-only and active on home.
- [ ] Contact tab is active on Contact route.
- [ ] Portfolio tab is active while locked and unlocked on Portfolio route.
- [ ] About Me tab is active on About route.
- [ ] Each active tab exposes `aria-current="page"` or equivalent.
- [ ] Keyboard focus order is logical and visible.
- [ ] Verify in browser using dev-browser skill.

### US-002: Direct URL State

As a visitor, I can load each tab URL directly and see the matching state.

Acceptance criteria:

- [ ] `/` loads Home.
- [ ] `/contact.html` loads Contact route.
- [ ] `/about.html` loads About route.
- [ ] `/portfolio.html` without access loads the in-window Portfolio gate.
- [ ] `/portfolio.html` with access loads the Portfolio deck.
- [ ] Back/forward works without stale modal flags.
- [ ] Verify in browser using dev-browser skill.

### US-003: Same About Page For About And CV URLs

**Description:** As a visitor with an old CV link, I want `/cv.html` to show the same page as `/about.html` so existing links do not break.

**Acceptance Criteria:**
- [ ] `/about.html` and `/cv.html` resolve to the same non-gated About route state.
- [ ] The active tab is About Me for both URLs.
- [ ] No CV/About gate request is created for either URL.
- [ ] Verify in browser using dev-browser skill.

## 4. Functional Requirements

- FR-1: Add Contact and About route definitions.
- FR-2: Remove `cv` from active gate requirements.
- FR-3: Preserve compatibility for existing `/cv.html` links by making `/cv.html` the same page as `/about.html` via redirect or alias.
- FR-4: Centralize bottom tab route data instead of duplicating route labels across pages.
- FR-5: Active tab state must derive from route state, not modal state.
- FR-6: Do not introduce a second route transition owner.
- FR-7: Add `contact.html`, `about.html`, `src/entries/contact.jsx`, `src/entries/about.jsx`, and Vite Rollup input entries.
- FR-8: Add stable semantic selectors for bottom tabs, such as `data-route-tab`, before audit migration starts.
- FR-9: Update `ROUTE_DEFS` in `react-app/app/src/lib/routes.js` so `contact` and `about` are first-class route IDs and `cv` is a compatibility alias or redirect for the About route.
- FR-10: Update `react-app/app/vite.config.js` Rollup input entries so `dist/contact.html` and `dist/about.html` are generated by `npm run build`.
- FR-11: Update route rendering in `SiteApp.jsx` so Contact, About, Portfolio locked, and Portfolio unlocked all have explicit route surfaces.
- FR-12: Remove `cv` from route-level gate definitions while preserving Portfolio as gated.
- FR-13: Update `isRouteBaselineReady` and route-ready selectors in `useShellRouteTransition.js` so home readiness depends on the new bottom tab shell selectors, not only `#main-links .footer_link`.
- FR-14: Define bottom-tab route data with IDs, hrefs, labels, and accessibility names:
  - Home: route ID `home`, href `/index.html`, icon-only visual, accessible name `Home`.
  - Contact: route ID `contact`, href `/contact.html`, label `Contact`.
  - Portfolio: route ID `portfolio`, href `/portfolio.html`, label `Portfolio`.
  - About Me: route ID `about`, href `/about.html`, label `About Me`.
- FR-15: Keep `contents-home.json` footer link copy as compatibility/source copy only until a deliberate content-source cleanup removes it.

## 5. Non-Goals

- No final Portfolio deck redesign.
- No new About content beyond coming soon.
- No global restyle of every `.footer_link`.

## 6. Technical Considerations

- Update `routes.js`, `access-gates.js`, `SiteApp.jsx`, `useShellRouteTransition.js`, route components, and navigation helpers together.
- Update `react-app/app/vite.config.js` and HTML entry files for direct static loads.
- Current Vite inputs include `index`, `portfolio`, `cv`, and styleguide/lab pages, but not `contact` or `about`.
- Current `routes.js` defines `portfolio.gated = true` and `cv.gated = true`; implementation must make Portfolio the only gated route.
- Current `access-gates.js` has `portfolio` and `cv` access/request keys; implementation must remove CV/About gate use.
- Current `useShellRouteTransition.js` checks `#main-links .footer_link` for home readiness; update this before moving/removing `#main-links`.
- Current audits reference `#main-links` and legacy modal triggers; later PRDs must migrate those selectors.
- Keep legacy aliases explicit and temporary.
